🎯 Lab Overview

By the end of lab, you will:

  1. Connect your assistant to voice using browser_audio

  3. Build a Voice-Enabled Library Assistant
  4. Verify logic over REST, then test real-time voice behavior
  5. Demonstrate interruption handling (barge-in) live

✅ Does Rasa support voice? Yes.

Rasa Pro CALM is channel-agnostic: the same flows, slots, and patterns work for text and voice.

  • Text channel: rest (JSON in/out)
  • Voice channel: browser_audio (mic streaming + ASR + CALM + TTS)

🔊 Voice Provider Options

Provider ASR TTS Notes
Deepgram ✅ ✅ Streaming both directions; simplest setup
Cartesia — ✅ Streaming TTS
Azure Speech ✅ ✅ TTS does not support streaming
Rime — ✅ No streaming, 24kHz only

This lab uses Deepgram for both ASR and TTS.

💡 Why this deserves its own lab

Voice exposes HAI concepts text chat hides:

  • Turn-taking + barge-in (can users interrupt?)
  • Latency is felt in spoken interaction
  • No visual affordances (everything must work as speech)
  • Silence/no-input handling is critical

Lab 3 focus: make these concepts concrete and testable in class.

🧰 Part 1 — Setup

1.1 Get a free Deepgram API key

Sign up at deepgram.com or console.deepgram.com/signup.

  • No credit card required
  • $200 free credit

1.2 Export the key

export DEEPGRAM_API_KEY="<your deepgram api key>"

Tip: add this to .venv/bin/activate like your RASA_LICENSE.

🧪 1.3 Confirm browser_audio channel in credentials.yml

browser_audio:
  server_url: localhost
  interruptions:
    enabled: false
    min_words: 3
  asr:
    name: deepgram
  tts:
    name: deepgram
  • enabled: allow mid-speech interruption (barge-in)
  • min_words: minimum partial transcript words before interrupt triggers

🏗️ Part 2 — Build: Voice-Enabled Library Assistant

Two flows:

  1. Quick spoken Q&A (hours)
  2. Slow lookup flow (availability) for latency/filler-response design

2.1 Add slots (domain.yml)

room_type:
  type: categorical
  values:
    - "quiet"
    - "group"
    - "media"
  mappings:
    - type: from_llm
room_status:
  type: text
  mappings:
    - type: controlled

room_status is controlled because your custom action sets it (not user speech).

2.2 Declare custom action (domain.yml)

⚠️ Must be explicitly listed under top-level actions:

actions:
  - action_check_room_availability

If omitted, you’ll get: action used in flow but not listed in domain.

2.3 Add responses (domain.yml)

utter_library_hours:
  - text: "The library is open Monday through Friday, 8am to midnight, and weekends 10am to 8pm."
utter_ask_room_type:
  - text: "Would you like a quiet room, a group room, or a media room?"
utter_please_wait_room_check:
  - text: "One moment, let me check that for you."
utter_room_availability_result:
  - text: "Here's what I found: the {room_type} room is {room_status}."

2.4 Add flows (data/flows.yml)

tell_library_hours:
  description: User wants to know the library's opening hours.
  steps:
    - action: utter_library_hours

check_room_availability:
  description: User wants to check whether a study room is available to book.
  steps:
    - collect: room_type
    - action: utter_please_wait_room_check
    - action: action_check_room_availability
    - action: utter_room_availability_result

✅ Key ordering: filler response → slow action → result.

2.5 Add custom action (actions/actions.py)

class ActionCheckRoomAvailability(Action):
    def name(self) -> Text:
        return "action_check_room_availability"

    def run(
        self,
        dispatcher: CollectingDispatcher,
        tracker: Tracker,
        domain: Dict[Text, Any],
    ) -> List[Dict[Text, Any]]:
        # Simulates a slow backend lookup.
        time.sleep(3)

        room_type = tracker.get_slot("room_type")
        hardcoded_status = {
            "quiet": "available now",
            "group": "booked until 3pm",
            "media": "available now",
        }
        room_status = hardcoded_status.get(room_type, "not found")
        return [SlotSet("room_status", room_status)]

Note: add import time if needed.

⚙️ Execution Note

endpoints.yml already contains:

action_endpoint:
  actions_module: "actions"

So actions run embedded in the assistant process.
No separate rasa run actions needed for this lab.

🔍 Part 3 — Verify Over Text First

Before audio debugging, validate logic quickly via REST.

rasa data validate
rasa train
rasa run --enable-api --cors "*"

🔍 REST Test Conversation

curl -s -X POST http://localhost:5005/webhooks/rest/webhook -H "Content-Type: application/json" -d '{"sender": "voice_demo", "message": "is a study room available?"}'
[{"recipient_id":"voice_demo","text":"Would you like a quiet room, a group room, or a media room?"}]
curl -s -X POST http://localhost:5005/webhooks/rest/webhook -H "Content-Type: application/json" -d '{"sender": "voice_demo", "message": "quiet"}'
[{"recipient_id":"voice_demo","text":"One moment, let me check that for you."},{"recipient_id":"voice_demo","text":"Here's what I found: the quiet room is available now."},{"recipient_id":"voice_demo","text":"Is there anything else I can do for you?"}]

🧠 Important Caveat (Discuss in Class)

REST buffers full turn output and returns one JSON array.
So filler-response timing is not perceived over REST.

  • REST = validates logic
  • Streaming voice channel = reveals UX timing behavior

Same flow, different user experience by channel.

🎧 Part 4 — Deploy: Talk to It For Real

Stop REST server (Ctrl+C) and launch Inspector:

rasa inspect

Open the provided localhost URL in Chrome and allow microphone access.

Look for voice_channel.initialized in terminal logs.

🗣️ 4.3 Run the voice conversation

Try saying:

  • “Is a study room available?”
  • “quiet”
  • “What time does the library close?”

You should hear TTS playback of assistant replies.

🚦 Part 5 — Live Demo: Barge-In (Interruptions)

5.1 With interruptions disabled

Current config:

interruptions:
  enabled: false
  min_words: 3

Assistant finishes speaking even if user talks over it.

🚦 5.2 Enable interruptions

Edit credentials.yml:

browser_audio:
  interruptions:
    enabled: true
    min_words: 3

Restart rasa inspect, then interrupt mid-sentence with 3+ words
(e.g., “wait, stop, change it to group”).

💬 5.3 Discussion Prompts

  • Why min_words: 3 instead of 1?
  • During time.sleep(3), what is interruptible: speaking, thinking, or both?
  • Which human turn-taking cues does a word-threshold approximate — and miss?

credentials.yml edits ignored Server not restarted Restart rasa inspect
Feedback loop Mic picks up speaker output Use headphones
