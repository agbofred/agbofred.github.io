📦 Part 1 — Pull Starter Project

rasa init --template tutorial

Why tutorial template? - Uses free hosted Rasa tutorial LLM - No OpenAI billing/API-key setup needed for students

🗂️ What the Scaffold Includes

File/Folder Purpose
config.yml CALM config (CompactLLMCommandGenerator, FlowPolicy)
domain.yml Slots + responses
data/flows.yml Conversation business logic
data/patterns.yml Built-in repair flows
actions/ Custom Python actions
credentials.yml Channel connectors (REST default)
endpoints.yml LLM/action server endpoints

🧩 Part 2 — Core CALM Concepts

  • description: flow trigger intent (LLM-readable)
  • collect: request and fill slot
  • Slots typed memory (text, categorical, float, …)
  • Patterns built-in repair/handoff/chitchat flows

⭐ Key feature for demo: digressions (pause current flow, handle interruption, then resume)

🟢 Part 3 — Scenario 1: Course FAQ Assistant

Goal: Trigger flows + static responses (no slot collection)

Add flows in data/flows.yml

flows:
  tell_office_hours:
    description: User wants to know instructor office hours.
    steps:
      - action: utter_office_hours

  tell_syllabus_location:
    description: User wants to know where to find the course syllabus.
    steps:
      - action: utter_syllabus_location

  tell_assignment_deadline:
    description: User wants to know when an assignment is due.
    steps:
      - action: utter_assignment_deadline

🟢 Scenario 1 — Responses in domain.yml

responses:
  utter_office_hours:
    - text: "Office hours are Tue/Thu 2–3pm in Ford 210, or by appointment."
  utter_syllabus_location:
    - text: "The syllabus is posted on the course Canvas page, under Files."
  utter_assignment_deadline:
    - text: "Check the Canvas calendar for exact due dates — they vary by assignment."

⚠️ Keep one responses: block only.

🟡 Part 4 — Scenario 2: IT Help-Desk Assistant

Goal: slot collection + conditional branching + digressions/corrections

Add slots (domain.yml)

slots:
  issue_category:
    type: categorical
    values: ["hardware", "software", "account_access", "other"]
    mappings:
      - type: from_llm
  issue_description:
    type: text
    mappings:
      - type: from_llm
  urgency:
    type: categorical
    values: ["low", "medium", "high"]
    mappings:
      - type: from_llm

🟡 Scenario 2 — Add Responses

responses:
  utter_ask_issue_category:
    - text: "What kind of issue is this — hardware, software, or account access?"
  utter_ask_issue_description:
    - text: "Briefly describe the problem."
  utter_ask_urgency:
    - text: "How urgent is this — low, medium, or high?"
  utter_escalate:
    - text: "This looks urgent — flagging it for immediate review."
  utter_ticket_summary:
    - text: "Ticket created: {issue_category} issue — '{issue_description}', urgency: {urgency}."

🟡 Scenario 2 — Flow with Branching

submit_it_ticket:
  description: User wants to report a tech problem or request IT help.
  steps:
    - collect: issue_category
    - collect: issue_description
    - collect: urgency
      next:
        - if: slots.urgency == "high"
          then:
            - action: utter_escalate
            - link: pattern_human_handoff
        - else:
            - action: utter_ticket_summary
              next: END

🔍 Scenario 2 — What to Test

  1. Clean run: fill all slots → ticket summary
  2. Digression: interrupt mid-flow, ask ticket status, resume prior flow
  3. Correction: change urgency after initial value

Commands:

rasa data validate
rasa train
rasa inspect

🧯 Part 5 — Troubleshooting Cheat Sheet

Symptom Cause Fix
duplicate flows/responses key second top-level header added keep one block
CategoricalSlot ... unexpected keyword slot indentation error align slot names
missing a 'next' in branch terminal step without next add next: END
invalid choice: 'validate' wrong command rasa data validate
address already in use port conflict free port/process
license.not_found.error env var unset export license
