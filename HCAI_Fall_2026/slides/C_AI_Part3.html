Week 6: Training Your Assistant (Chapter 6)

Visual: Part 3 Roadmap

Slide 1: Training Data Principles

  • The 3 V’s of NLU Data Quality:
  • Volume: Sufficient utterances per intent (minimum target: 20–50 distinct examples).
  • Variety: Structural, lexical, and syntactical diversity (slang, typos, synonyms, length variations).
  • Veracity: Clean, correctly labeled ground truth data without misallocations.

Visual: The 3 V’s of NLU Data Quality

Infographic: Data Quality Balance

Slide 2: Sourcing Training Data

  • Historical Logs: Live customer service chat logs, email threads, call center transcripts.
  • Domain Subject Matter Experts (SMEs): Gathering common phrasing patterns directly from frontline support staff.
  • Synthetic Generation: Using controlled augmentation strategies to expand low-sample intents.

Slide 3: Managing Intent Overlap

  • Intent Collisions: When two intents share highly similar training phrases (e.g., #Cancel_Order vs. #Return_Item).
  • Disambiguation Rules: Merging overlapping intents into a single broad intent or separating them using mandatory entity constraints.

Week 7: Evaluating Assistant Accuracy (Chapter 7)

Visual: Evaluation Loop

Slide 1: Empirical Testing Frameworks

  • Train / Test Splits: Splitting raw data into separate sets (e.g., 80% Training Set, 20% Holdout Test Set).
  • Blind Testing: Evaluating models against uncleaned, real-world user data collected after the training phase.
  • Cross-Validation: \(k\)-fold cross-validation to assess dataset stability and highlight underfitting.

Visual: Train/Test + Cross-Validation Workflow

Slide 2: Machine Learning Metrics

\[\text{Precision} = \frac{TP}{TP + FP} \quad \vert{} \quad \text{Recall} = \frac{TP}{TP + FN}\]

\[\text{F1 Score} = 2 \cdot \frac{\text{Precision} \cdot \text{Recall}}{\text{Precision} + \text{Recall}}\]

  • True Positive (\(TP\)): Correctly assigned intent.
  • False Positive (\(FP\)): Incorrectly assigned intent (over-triggering).
  • False Negative (\(FN\)): Failed to detect correct intent (under-triggering).

Visual: Precision vs Recall Tradeoff

Slide 3: Analyzing Confusion Matrices

  • Confusion Matrix: A square matrix mapping predicted intents against ground-truth labels.
  • Diagonal Values: High values indicate strong model accuracy.
  • Off-Diagonal Values: Highlight intent collisions and misclassifications needing data cleanup.

Week 8: Testing Dialogue Flows (Chapter 8)

Visual: End-to-End Testing Stack

Slide 1: Structural Flow Validation

  • Path Coverage: Validating every branch, conditional logic block, and node transition within the dialogue engine.
  • Automated Flow Testing: Scripting end-to-end conversation trees to run automatically during continuous integration builds.

Visual: Dialogue Path Coverage Map

Slide 2: Edge Case & Boundary Stress Testing

  • Unexpected Inputs: Testing user interruptions, mid-flow intent switching (digressions), and invalid payload types.
  • Context Bleed: Ensuring previous turn entities do not overwrite new session contexts when changing topics.

Visual: Edge Case Test Matrix

Test Type Example Input Expected Behavior

Mid-flow switch “Actually cancel it” Preserve safety checks, switch branch cleanly

Context reset “New topic: billing” Clear stale entities from old task

Slide 3: Non-Functional & Performance Testing

  • Load / Concurrency Testing: Verifying system performance under high simultaneous user traffic.
  • API Latency Checks: Ensuring back-end fulfillment webhooks respond within 1–2 seconds to prevent conversation drop-offs.
